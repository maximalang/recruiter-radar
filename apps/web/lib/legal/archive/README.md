# Legal document archive (immutable revision snapshots)

Каждый файл `documents/<key>-<revision>.md` — замороженный снимок публичного
документа на момент ревизии, указанной в `apps/web/lib/legalDocuments.ts`.
Файлы никогда не редактируются после публикации: изменение документа = новый
файл с новой датой-ревизией + обновление `manifest.json`.

`manifest.json` содержит SHA-256 каждого снимка; Jest-контракт
`legal-revisions.test.ts` проверяет: (1) текущая ревизия каждого checkout-
документа имеет архивный файл и совпадающий хэш; (2) манифест не теряет записи.

Порядок выпуска новой версии:

1. Внести текстовые изменения на странице.
2. Скопировать прежний снимок в archive (если его там ещё нет) — уже сделано
   для базовой ревизии 2026-08-05.
3. Создать новый снимок с новой ревизией.
4. Обновить даты в `legalDocuments.ts` и `manifest.json` (пересчитать хэши:
   `node apps/web/scripts/hash-legal-archive.mjs`).
5. Прогнать `npm run test --workspace @recruiter-radar/web -- legal-revisions`.

Checkout записывает в заказ ревизии четырёх документов + `legalSetRevision`
(версия семантики набора). По ревизиям из заказа снимки восстанавливаются
однозначно — это и есть доказуемость исторического акцепта.
