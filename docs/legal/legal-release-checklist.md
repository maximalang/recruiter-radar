# Legal release checklist

Перед релизом, меняющим правовую поверхность (тексты документов, consent-логика,
checkout-контракт, процессоры, каналы доставки):

1. **Ревизии.** Изменённым документам присвоена новая дата-ревизия в
   `apps/web/lib/legalDocuments.ts`; для каждого изменения создан архивный файл в
   `apps/web/lib/legal/archive/`; манифест хэшей обновлён; Jest-контракт
   `legal-revisions` зелёный.
2. **Checkout-контракт.** Два отдельных checkbox, оба не предотмечены, сервер
   отклоняет отсутствие любого из них; ревизии фиксируются в заказе (тесты
   `checkout-legal-contract`).
3. **Cookies/аналитика.** Метрика не стартует без согласия; отказ равен согласию по
   простоте; «Настроить» открывает диалог; отзыв останавливает сбор; Playwright-сценарии
   зелёные.
4. **Синхронизация фактов.** Цены/сроки — из `PUBLIC_PLANS`; реквизиты — из
   `OPERATOR_REQUISITES`; запрет автопродления и массовой рассылки не нарушен
   (контракты `legal-content-contracts` + `verify-robokassa-site-criteria.mjs`).
5. **Процессоры/каналы.** Новый провайдер/канал → обновить `processor-register.md`,
   `data-map.md`, `/privacy` §10, при трансграничке — сначала counsel-решение.
6. **Retention.** Изменение сроков хранения → сверить `retention-schedule.md` с
   механизмами; не заявлять срок без механизма.
7. **RKN.** Изменение целей/категорий данных → пересмотреть чек-лист
   `roscomnadzor-checklist.md` и (при необходимости) уведомление.
8. **Скриншот-гейт.** Все правовые страницы на 1440×900 и 390×844: таблицы не
   обрезаны, навигация работает, ревизия и реквизиты видны.
9. **Верификация.** `npm run web:check`, Jest (правовые контракты), Playwright
   (legal/cookie/checkout), production build, `git diff --check`, secret scan,
   скан абсолютных путей.
10. **PR.** Один PR, тело содержит evidence по шаблону; PR не мержится без владельца.
