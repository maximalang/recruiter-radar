# Расписание хранения и удаления (retention schedule)

Принцип: публичная Политика не должна заявлять срок, который не исполняется
технически или процессно. Ниже — сверка каждого заявленного срока с механизмом.

Статусы: ENFORCED — автоматика/скрипт; MANUAL — ручной процесс; MISSING —
механизма нет (в Политике такие сроки смягчены до «при необходимости»/«по решению
оператора» либо помечены ACTION REQUIRED).

| Класс данных | Заявлено в `/privacy` | Реальность в коде | Механизм | Статус |
|---|---|---|---|---|
| Аккаунт, профиль | удаление аккаунта; при необходимости до 3 лет для споров | self-service запрос удаления (`/settings/security`), затем отложенный purge | `purge-auth-v2-accounts.mjs` + `AUTH_ACCOUNT_PURGE_AFTER_DAYS` | ENFORCED (при настроенном env; иначе manual review — задокументировано) |
| Одноразовые коды/challenges | технический срок | `auth_challenges` c expires_at | скрипт `auth:cleanup-challenges` | ENFORCED (запуск по расписанию ops) |
| Сессии | до отзыва | отзыв при удалении аккаунта, ротация | `account-security.ts` | ENFORCED |
| Журналы безопасности (`auth_security_events`) | обычные — 1 год; материалы инцидента — до завершения расследования | таблица append-only, TTL отсутствует | отсутствует | MISSING → ACTION REQUIRED. Формулировка Политики смягчена («обычно», «если не установлено иное») до внедрения TTL |
| Профили радара, фидбек | жизнь аккаунта + до 3 лет | отключение профилей при запросе удаления; физическое удаление после purge | purge script | ENFORCED на уровне доступа; физическое удаление — по purge_after |

| Возвраты | 3 года | `payment_refunds`, удаления нет | отсутствует | MANUAL — удержание оправдано |
| Webhook events | не заявлено | накапливаются | отсутствует | MISSING → добавить в будущий cleanup; в Политике срок не заявлялся — ок |
| product_telemetry_events | не заявлено публично | накапливаются | отсутствует | MISSING → ACTION REQUIRED (внутренняя задача); публичных обещаний нет |
| Поддержка (почта) | обычно до 3 лет после закрытия | почтовый ящик провайдера | ручная чистка | MANUAL — формулировка «обычно» соответствует |

## Публичные формулировки

Политика использует связку «срок X» только там, где есть механизм (аккаунт,
challenges, Метрика). Для классов без автоматики применяются обороты «обычно»,
«при необходимости», «в пределах применимого срока» — чтобы текст не расходился с
реальностью. Как только TTL-механизмы добавлены, формулировки можно усилить.

## Бэклог внедрения (не входит в этот PR)

1. TTL-джоб для `auth_security_events` старше 1 года (кроме инцидентных).
2. TTL-джоб для `product_telemetry_events` (например, 24 месяца).
3. Ротация/вынос бэкапов с верифицированным restore drill.
