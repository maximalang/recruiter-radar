# Runbook: запросы субъектов персональных данных

Область: запросы (1) пользователей сервиса и (2) третьих лиц, чьи минимальные
профессиональные сведения могут встречаться в evidence-карточках.
Публичные точки входа: support@recruiter-radar.ru, `/data-policy`, `/privacy` §14.

## Чек-лист обработки (каждый шаг фиксируется в тикете)

1. **Запрос получен.** Зафиксировать дату получения (начало срока), канал, суть.
2. **Идентификация/связь.** Найти аккаунт по e-mail; для внешнего субъекта —
   соразмерное подтверждение связи (достаточно: ссылка на конкретную карточку/страницу
   где встречаются данные, или совпадение e-mail). Паспорт по умолчанию не запрашивается.
3. **Поиск по системам.** Пройти по data-map.md:
   PostgreSQL (аккаунт, профиль, заказы, телеметрия), почта поддержки, бэкапы
   (учитываются, отдельного удаления не требуют до цикла перезаписи), Яндекс.Метрика
   (обезличено; субъекту объяснить), каналы доставки.
4. **Правовое основание решения.** Проверить, не входит ли запрошенное в правомерное
   удержание (налоговые/договорные сроки — заказы, чеки, возвраты). Удержание —
   частичное: данные удаляются везде, кроме обязанного класса.
5. **Исполнение.**
   - доступ: выписка по категориям/целям/срокам (без раскрытия служебных деталей);
   - уточнение: правка записи;
   - удаление: аккаунт — через `/settings/security` (отложенный purge), внешние
     субъекты — правка/suppression записи источника;
   - ограничение/блокировка: флаг в записи до разрешения спора.
6. **Процессоры.** Если данные передавались процессору (почта, Robokassa) — при
   необходимости уведомить в рамках их процедур.
7. **Ответ.** 10 рабочих дней; продление до 5 с мотивированным уведомлением.
8. **Аудит-запись.** Сохранить: дату, запрос, решение, объём изменений, срок ответа.

## Специфика внешних субъектов (публичные источники)

- Запрос «это не я / ошибочная связь с организацией» → правка или удаление связи
  (entity-resolution правка), suppression от будущей выдачи.
- Запрос на удаление профессиональных сведений → удалить/обезличить в БД и
  исключить из клиентской выдачи; исходная публикация источника не контролируется —
  предложить субъекту обратиться к источнику.
- Сроки и основания — см. legal-research-2026-08.md §8 (ст. 8, 14, 21 152-ФЗ).

## Что не раскрывается в ответе

Внутренние детали безопасности, полные журналы других субъектов, коммерческие
алгоритмы скоринга (объяснение решения — на уровне категорий).
