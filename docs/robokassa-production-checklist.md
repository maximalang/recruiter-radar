## 2. Описание деятельности для анкеты

> Recruiter Radar — информационно-аналитический онлайн-сервис для рекрутинговых агентств. Сервис анализирует открытые hiring signals российских компаний и формирует подборки компаний, которым актуально предложить услуги подбора. Клиент получает доступ к личному кабинету, доказательствам сигнала, оценке уверенности и настроенному каналу доставки. Физическая доставка отсутствует.

Категория: программное обеспечение / информационно-аналитические услуги / доступ к онлайн-сервису.

Способ оказания услуги: цифровой доступ через сайт и подключённые клиентом каналы доставки.

## 5. Настройка тестового магазина

В deployment environment:

```env
PAYMENTS_PROVIDER=robokassa
ROBOKASSA_MODE=test
ROBOKASSA_MERCHANT_LOGIN=<merchant login>
ROBOKASSA_HASH_ALGORITHM=sha256
ROBOKASSA_TEST_PASSWORD_1=<test password 1>
ROBOKASSA_TEST_PASSWORD_2=<test password 2>
ROBOKASSA_RESULT_URL=https://recruiter-radar.ru/api/billing/webhook/robokassa
PAYMENTS_SITE_URL=https://recruiter-radar.ru
```

В кабинете Robokassa:

- Result URL: `https://recruiter-radar.ru/api/billing/webhook/robokassa`
- Метод Result URL: `POST`
- Алгоритм хеширования должен совпадать с `ROBOKASSA_HASH_ALGORITHM`.
- Success/Fail URL передаются отдельно для каждого заказа через подписанные параметры.
- Не включать рекуррентные списания.
- Не подключать 54-ФЗ кассу для продавца на НПД.

## 6. Тестовый платёж

Для каждого тарифа:

- [ ] Создать заказ из подтверждённого аккаунта.
- [ ] Сверить сумму, срок и отсутствие автосписания.
- [ ] Проверить переход на домен Robokassa.
- [ ] Завершить тестовую оплату.
- [ ] Убедиться, что один browser SuccessURL не активирует заказ.
- [ ] Получить подписанный ResultURL.
- [ ] Убедиться, что ответ сервера равен `OK{InvId}`.
- [ ] Проверить статус `paid`.
- [ ] Проверить выдачу доступа на 7, 30 или 90 дней.
- [ ] Повторить тот же ResultURL и убедиться, что доступ не продлился второй раз.
- [ ] Проверить неверную подпись, сумму и `Shp_plan` — запрос должен быть отклонён.

После полного прохождения указать фактическое время:

```env
ROBOKASSA_TEST_FLOW_VERIFIED_AT=<ISO 8601>
```

## 8. Live-настройка и возвраты

После одобрения магазина:

```env
ROBOKASSA_MODE=live
ROBOKASSA_PASSWORD_1=<live password 1>
ROBOKASSA_PASSWORD_2=<live password 2>
ROBOKASSA_PASSWORD_3=<live password 3>
ROBOKASSA_REFUND_JWT_ALGORITHM=HS256
```

- Password1 используется для создания платёжной ссылки.
- Password2 проверяет ResultURL и используется для OpStateExt.
- Password3 подписывает JWT Refund API.
- Секреты никогда не передаются в браузер и не записываются в Git.

Проверка возвратов:

- [ ] Создать частичный возврат через `/admin/payments`.
- [ ] Проверить резервирование суммы в PostgreSQL.
- [ ] Получить `requestId` Robokassa.
- [ ] Синхронизировать состояние до `finished`.
- [ ] Убедиться, что частичный возврат не отзывает доступ.
- [ ] Вернуть оставшуюся сумму.
- [ ] Убедиться, что заказ стал `refunded`.
- [ ] Убедиться, что срок доступа пересчитан по оставшимся оплаченным заказам.
- [ ] Проверить невозможность вернуть больше оплаченной суммы.

После фактической проверки:

```env
ROBOKASSA_REFUND_FLOW_VERIFIED_AT=<ISO 8601>
```
