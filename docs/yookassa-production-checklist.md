# Recruiter Radar — регистрация, тестирование и запуск ЮKassa

Документ является рабочей инструкцией для владельца и разработчика. Код намеренно остаётся fail-closed: отсутствие адреса, ключей, webhook или подтверждённых проверок не позволит readiness-отчёту показать `live-ready`.

Официальные источники:

- подключение: https://yookassa.ru/docs/support/payments/onboarding/overview
- регистрация: https://yookassa.ru/docs/support/merchant/payments/implement/start
- тестовый магазин: https://yookassa.ru/docs/support/merchant/payments/implement/test-store
- возвраты: https://yookassa.ru/docs/support/merchant/payments/refunds
- данные для договора: https://yookassa.ru/docs/support/merchant/payments/implement/docs
- «Мой налог»: https://npd.nalog.ru/web-app/

## 1. Что уже реализовано

- [x] Реальные тарифы и сроки берутся из `PUBLIC_PLANS`.
- [x] Checkout показывает услугу, тариф, срок, итог и отсутствие автосписаний.
- [x] Оферта описывает оформление, цифровое предоставление, отказ и возврат.
- [x] Политика ПДн, отдельное согласие и реквизиты опубликованы.
- [x] Публичные контакты: `support@recruiter-radar.ru`, `+7 900 966-60-92`.
- [x] ЮKassa API работает fail-closed и сверяет заказ, сумму, валюту, metadata и test/live режим.
- [x] Webhook повторно проверяет платежи и возвраты через API ЮKassa.
- [x] Полный возврат делает заказ терминальным и отзывает оплаченный доступ.
- [x] Успешный платёж создаёт в PostgreSQL задачу на чек НПД.
- [x] Полный возврат после выдачи чека создаёт задачу на его аннулирование.
- [x] Операторская очередь доступна на `/admin/payments`.
- [x] Ссылка на чек из «Мой налог» отправляется клиенту через настроенную почту.
- [x] Три стадии readiness проверяются командами `registration`, `test`, `live`.

## 2. Единственный недостающий публичный реквизит

Указать фактический адрес для корреспонденции:

```dotenv
OPERATOR_PUBLIC_POSTAL_ADDRESS=<реальный индекс, регион, город, улица, дом, квартира при наличии>
```

Адрес нельзя заменять адресом хостинга, виртуальным офисом без права получения корреспонденции или вымышленным значением.

## 3. Подготовка окружения

Использовать шаблон `.env.yookassa.example`.

Для проверки сайта перед регистрацией:

```bash
npm run payments:yookassa:preflight:registration --workspace @recruiter-radar/web
```

Команда проверяет:

- публичный email, телефон и адрес;
- канонические URL сайта и webhook;
- доступность оферты, политики, согласия, реквизитов и checkout;
- HTTPS;
- наличие почтового транспорта для отправки НПД-чеков;
- доступ оператора и readiness API.

## 4. Ответы для регистрации ЮKassa

### Организационный статус

`Самозанятый / плательщик налога на профессиональный доход (НПД)`.

### Где принимаются платежи

`На сайте`.

### Адрес сайта

`https://recruiter-radar.ru`.

### Название магазина или сервиса

`Recruiter Radar`.

### Описание деятельности

> Recruiter Radar — онлайн-сервис для рекрутинговых агентств. Сервис анализирует открытые сигналы найма российских компаний и предоставляет пользователю цифровые подборки потенциальных клиентов с источниками, оценкой актуальности и рекомендациями для первого делового контакта.

### Что получает покупатель

> Оплаченный доступ к личному кабинету Recruiter Radar, настройке профиля поиска и цифровым подборкам компаний с hiring signals. Физическая доставка отсутствует.

### Категория

Выбирать наиболее близкую категорию `услуги / цифровые услуги / информационно-аналитические услуги`. Не выбирать кадровое агентство от имени Recruiter Radar: сервис не подбирает кандидатов и не гарантирует найм.

### Схема оплаты

> Разовая оплата выбранного периода. Автоматическое продление, рекуррентные списания и сохранение платёжного средства не используются.

### Возвраты

> Клиент направляет запрос на support@recruiter-radar.ru. Возможен полный или частичный возврат через ЮKassa на исходный способ оплаты. После полного возврата доступ по заказу прекращается, чек НПД аннулируется с причиной «Возврат средств».

### Контакты

- email: `support@recruiter-radar.ru`
- телефон: `+7 900 966-60-92`
- адрес: значение `OPERATOR_PUBLIC_POSTAL_ADDRESS`

### Интеграция

`Самостоятельная интеграция по API`.

### Чеки и налоговый режим

Не подключать сервис `Чеки от ЮKassa`: официальная документация ЮKassa прямо указывает, что он не подходит плательщикам НПД. Чеки формируются в «Мой налог», через разрешённого оператора электронной площадки или банк.

Если интерфейс регистрации показывает только варианты онлайн-касс по 54-ФЗ и не предлагает корректный вариант для НПД, не выбирать кассу наугад — открыть чат поддержки ЮKassa и указать, что подключается физлицо-самозанятый на НПД.

## 5. Тестовый магазин

Тестовый магазин можно создать до заключения договора.

```dotenv
PAYMENTS_PROVIDER=yookassa
PAYMENTS_SITE_URL=https://recruiter-radar.ru
YOOKASSA_MODE=test
YOOKASSA_SHOP_ID=<test shopId>
YOOKASSA_SECRET_KEY=<test secret key>
YOOKASSA_WEBHOOK_URL=https://recruiter-radar.ru/api/billing/webhook/yookassa
```

В разделе `Интеграция → HTTP-уведомления` указать URL:

```text
https://recruiter-radar.ru/api/billing/webhook/yookassa
```

Выбрать события:

- `payment.succeeded`
- `payment.canceled`
- `payment.waiting_for_capture`
- `refund.succeeded`

После установки тестовых ключей:

```bash
npm run payments:yookassa:preflight:test --workspace @recruiter-radar/web
```

## 6. Обязательный тестовый сценарий

- [ ] Оформить тариф «Неделя» за 2 990 ₽ через реальный checkout сайта.
- [ ] Убедиться, что обычная карта не используется: только тестовые реквизиты ЮKassa.
- [ ] Проверить `pending → paid` и активацию доступа.
- [ ] Убедиться, что в `/admin/payments` появилась задача `pending_issue`.
- [ ] Создать тестовый/операционный чек НПД допустимым способом и сохранить HTTPS-ссылку.
- [ ] Проверить отправку ссылки на email клиента.
- [ ] Повторно доставить тот же webhook и убедиться, что второй доступ и вторая задача не созданы.
- [ ] Проверить отменённый и незавершённый платёж.
- [ ] Провести частичный возврат и убедиться, что доступ не отозван полностью.
- [ ] Провести полный возврат и убедиться, что заказ стал `refunded`.
- [ ] Убедиться, что в `/admin/payments` появилась задача `cancellation_required`.
- [ ] Аннулировать чек в «Мой налог» с причиной `Возврат средств` и зафиксировать выполнение.
- [ ] Повторно открыть старые success/cancel URL и убедиться, что доступ не восстановлен.

После успешной проверки сохранить ID тестового платежа и реальный timestamp:

```dotenv
YOOKASSA_VERIFICATION_PAYMENT_ID=<payment id>
YOOKASSA_LAUNCH_VERIFIED_AT=<ISO timestamp>
NPD_RECEIPT_FLOW_VERIFIED_AT=<ISO timestamp>
```

## 7. НПД-чек

Оплата банковской картой или электронным кошельком относится к расчёту с использованием электронного средства платежа, поэтому операционная политика Recruiter Radar — формировать чек без задержки после подтверждения оплаты.

Очередь `/admin/payments` хранит:

- заказ и payment ID;
- сумму и валюту;
- email покупателя;
- время оплаты и срок выдачи;
- ссылку и номер чека;
- статус отправки;
- необходимость аннулирования после полного возврата.

При полном возврате:

1. выполнить возврат в ЮKassa;
2. дождаться `refund.succeeded`;
3. открыть `/admin/payments`;
4. аннулировать ранее сформированный чек в «Мой налог»;
5. выбрать причину `Возврат средств`;
6. подтвердить задачу в операторской панели.

## 9. Production

После договора и получения live-реквизитов:

```dotenv
YOOKASSA_MODE=live
YOOKASSA_SHOP_ID=<live shopId>
YOOKASSA_SECRET_KEY=<live secret key>
```

Запустить:

```bash
npm run payments:yookassa:preflight:live --workspace @recruiter-radar/web
```

Затем:

- [ ] провести один настоящий контрольный заказ;
- [ ] сформировать и отправить настоящий чек НПД;
- [ ] выполнить контролируемый возврат;
- [ ] аннулировать чек с причиной `Возврат средств`;
- [ ] проверить, что `/api/health/payment-readiness` возвращает `live-ready`;
- [ ] только после этого включать публичный self-service checkout.

## 10. Что нельзя отмечать заранее

Не устанавливать verification timestamps только ради зелёного readiness. Они являются операционным доказательством, а не feature flag. До реального прохождения тестов PR остаётся draft, `YOOKASSA_MODE=live` не используется, а checkout работает fail-closed.
