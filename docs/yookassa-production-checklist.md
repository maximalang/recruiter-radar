# Recruiter Radar — checklist подключения ЮKassa

Этот документ фиксирует внешние шаги, которые нельзя честно закрыть одним изменением кода.

## 1. Публичная витрина

- [x] Реальные тарифы и сроки берутся из `PUBLIC_PLANS`.
- [x] Checkout показывает услугу, тариф, срок, итог и отсутствие автосписаний.
- [x] Оферта описывает оформление, цифровую выдачу, отказ и возврат.
- [x] Политика ПДн и реквизиты доступны из общего footer.
- [x] Публичные контакты: `support@recruiter-radar.ru`, `+7 900 966-60-92`.
- [ ] Указать фактический адрес для корреспонденции в `OPERATOR_PUBLIC_POSTAL_ADDRESS`.

## 2. Конфигурация тестового магазина

```dotenv
OPERATOR_PUBLIC_POSTAL_ADDRESS=<фактический адрес>

PAYMENTS_PROVIDER=yookassa
PAYMENTS_SITE_URL=https://recruiter-radar.ru
YOOKASSA_MODE=test
YOOKASSA_SHOP_ID=<test shop id>
YOOKASSA_SECRET_KEY=<test secret key>
YOOKASSA_WEBHOOK_URL=https://recruiter-radar.ru/api/billing/webhook/yookassa
```

В личном кабинете ЮKassa подписать webhook на:

- `payment.succeeded`
- `payment.canceled`
- `payment.waiting_for_capture`
- `refund.succeeded`

## 3. Обязательная проверка тестового контура

- [ ] Успешная оплата тарифа «Неделя» на 2 990 ₽.
- [ ] Повторная доставка одного webhook не создаёт второй доступ.
- [ ] Подмена `order_id`, суммы, валюты или test/live режима отклоняется.
- [ ] Незавершённый и отменённый платёж не выдаёт доступ.
- [ ] Частичный возврат сохраняет оставшийся оплаченный доступ.
- [ ] Полный возврат переводит заказ в `refunded` и прекращает доступ.
- [ ] Старые success/cancel URL не изменяют `refunded`.

После проверки записать реальный ISO timestamp:

```dotenv
YOOKASSA_LAUNCH_VERIFIED_AT=2026-07-31T00:00:00.000Z
```

## 4. НПД

- [ ] На успешную оплату сформировать чек в «Мой налог» или через разрешённого оператора.
- [ ] Направить чек на e-mail заказчика.
- [ ] При полном возврате аннулировать/скорректировать чек с причиной «Возврат средств».
- [ ] Проверить частичный возврат и корректировку суммы дохода.

После проверки:

```dotenv
NPD_RECEIPT_FLOW_VERIFIED_AT=2026-07-31T00:00:00.000Z
```

- [ ] Проверить размещение PostgreSQL, backups, logs и error tracking.

- [ ] Оформить внутренний перечень мер защиты, доступов, сроков хранения и реагирования на инциденты.

```dotenv
PDN_COMPLIANCE_VERIFIED_AT=2026-07-31T00:00:00.000Z
```

## 6. Production

Только после выполнения предыдущих разделов:

```dotenv
YOOKASSA_MODE=live
YOOKASSA_SHOP_ID=<live shop id>
YOOKASSA_SECRET_KEY=<live secret key>
```

- [ ] Провести один реальный контрольный заказ.
- [ ] Проверить платёж, webhook, активацию, чек НПД и возврат.
- [ ] Убедиться, что `/api/health/payment-readiness` возвращает `live-ready`.

До завершения checklist PR и production rollout не считаются готовыми к live.
